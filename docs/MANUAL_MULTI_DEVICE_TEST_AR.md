# دليل اختبار المزامنة والتحديث متعدد الأجهزة (Manual Multi-Device Test Script)

هذا المستند يوضح خطوات اختبار ميزة المزامنة والتحديث الحي بدون استخدام خوادم WebSocket (التحديث التلقائي كل 20 ثانية مع واجهة الرؤية - Page Visibility API).

## متطلبات الاختبار
1. متصفحان مختلفان (أو نافذة متصفح رئيسية ونافذة تصفح مخفي Incognito).
2. مستخدمان بصلاحيات مختلفة:
   - مستخدم بصلاحية رئيس مجلس الإدارة / مدير (يمتلك صلاحية الاطلاع على السرية `can_view_confidential = 1`).
   - موظف عادي / سكرتير (لا يمتلك صلاحية الاطلاع على السرية `can_view_confidential = 0`).

---

## الخطوات والاختبارات

### الاختبار الأول: التحديث التلقائي للبيانات غير السرية (مثال: إنشاء تعميم أو توجيه جديد)
1. **في المتصفح الأول (الموظف العادي):**
   - سجل الدخول بحساب موظف عادي وافتح لوحة التوجيهات أو المراسلات.
2. **في المتصفح الثاني (المدير):**
   - سجل الدخول بحساب مدير وقم بإنشاء توجيه جديد أو تعديل حالة معاملة عادية.
3. **ما يجب ملاحظته:**
   - خلال 20 ثانية كحد أقصى (أثناء بقاء علامة تبويب المتصفح الأول نشطة ومرئية)، تقوم خطاف المزامنة `useSyncPolling` بفحص مسار `/api/sync/version`.
   - عند رصد زيادة في عداد `non_confidential_version`، يتم تحديث القائمة تلقائياً في المتصفح الأول مع ظهور مؤشر لطيف "تم التحديث" في الأسفل، **دون فقدان أي مدخلات غير محفوظة** إن وجدت.

### الاختبار الثاني: عزل البيانات السرية عن المستخدمين غير المخولين
1. **في المتصفح الثاني (المدير):**
   - قم بإنشاء أو تعديل معاملة سرية أو حساسة للغاية (`confidential` أو `top-secret`).
2. **في المتصفح الأول (موظف غير مخول):**
   - افحص استجابة الخادم لطلب `/api/sync/version` (أو راقب شبكة المتصفح).
   - **ما يجب ملاحظته:** استجابة الخادم للمستخدم غير المخول تحتوي فقط على `{ non_confidential_version: ... }` **ولا تحتوي أبداً على حقل `confidential_version`**، مما يمنع تماماً أي تسريب لمعلومة وجود نشاط سري.

### الاختبار الثالث: احترام واجهة الرؤية (Page Visibility API)
1. قم بتصغير نافذة المتصفح أو الانتقال إلى علامة تبويب أخرى.
2. **ما يجب ملاحظته:** تتوقف طلبات الاستطلاع (Polling) مؤقتاً لتوفير موارد الجهاز والشبكة، وتستأنف فور العودة إلى علامة التبويب ورؤيتها.
