## 2. ما تم التحقق منه واختباره هندسياً (What is Verified)

1. **سلامة البناء والأنواع البرمجية (Build & Typing):**
   - نجاح تام لفحص TypeScript الصارم (`tsc --noEmit`) دون أي أخطاء أو تجاهل للأنواع.
   - تجميع الخادم الصافي وأدوات التشغيل في `dist-server/` باستخدام `esbuild` بحجم مدمج وخلو تام من أدوات التطوير أو ملفات `.ts`.
   - بناء الواجهة الأمامية React 19 بتنسيقات Tailwind CSS المضمنة دون أي روابط خارجية أو نصوص CDN عبر الإنترنت.

2. **أجنحة الاختبارات الآلية (Automated Test Suites):**
   - اجتياز 21 جناح اختبار آلي متكامل يضم أكثر من 160 اختباراً حقيقياً يفحص:
     - أمان المصادقة والجلسات وكعكات `HttpOnly SameSite=Strict` وتشفير `scrypt`.
     - مصفوفة الصلاحيات (RBAC) وعزل البيانات المصنفة سرية للغاية عن غير المصرح لهم.
     - الحماية الصارمة من الحقن والتعيين الشامل (Mass Assignment Prevention عبر Zod .strict()).
     - سلسلة التدقيق التشفيرية المترابطة (SHA-256 Cryptographic Audit Chain) ونقاط التحقق اللحظية لكشف الحذف والتلاعب.
     - النسخ الاحتياطي المشفر بـ AES-256-GCM والتحقق الفوري من سلامة الجداول واسترجاع الطوارئ بفك التشفير (`--decrypt`).
     - المزامنة الفورية متعددة الأجهزة كل 20 ثانية عبر واجهة الرؤية (Page Visibility API) وحفظ مسودات النماذج.
     - فحص الجاهزية الاحتياطية للخادم الاحتياطي الدافئ (`npm run standby:check`).

3. **التحقق من حزمة التثبيت دون اتصال (Offline Package Verification):**
   - إنشاء حزمة التثبيت الذاتية مع ملفات الربط الثنائية المجمعة مسبقاً وسجل المطابقة المشفر `MANIFEST.json`.
   - اختبار فك الضغط والتشغيل المستقل في بيئة معزولة بنجاح تام (`npm run smoke:package`).
   - اختبار ربط المكتبات الثنائية المحلية (`npm run verify:native`).

## 3. الحدود الفنية المعروفة (Known Limitations)

1. **غياب المصادقة الثنائية (No 2FA Support):**
   - يعتمد النظام حالياً على كلمات المرور المأمونة بـ `scrypt` وجلسات المتصفح المحمية. لا تتوفر ميزة المصادقة متعددة العوامل (2FA) في هذا الإصدار، ويجب عدم إتاحة النظام خارج الشبكة المحلية المباشرة إلا بعد حسمها.

2. **عدم الخضوع لمراجعة أمنية مستقلة (No Independent Security Review):**
   - خضع النظام لاختبارات وتحصينات برمجية موسعة من فريق التطوير الداخلي، ولكنه لم يخضع بعد لمراجعة أمنية أو تقييم واختبار اختراق من جهة سيبرانية مستقلة معتمدة.

3. **حالة بيئة Windows والخدمات التلقائية (Windows / HTTPS / NSSM Status):**
   - كافة الخطوات الإجرائية والتكوينات الخاصة ببيئة Windows وإدارة الخدمة عبر `NSSM` موثقة معمارياً في الأدلة، ولكن **لم يتم اختبارها عملياً على أجهزة فعلية في بيئة العمل الحالية (not yet tested)**؛ نظراً لأن بيئة التطوير والتحقق الحالية تعمل على Linux.

4. **فاصل التحديث التلقائي وتزامن الأجهزة (~20s Refresh Interval):**
   - يستغرق ظهور التعديل الجديد على الأجهزة الأخرى فترة تصل إلى نحو 20 ثانية (بسبب الاعتماد على الاستطلاع الدوري عبر Page Visibility API بدلاً من خوادم WebSockets المعقدة).

5. **سياسة التعديل المتزامن (Last-Save-Wins):**
   - في حال قيام مستخدمين اثنين بتعديل نفس السجل في اللحظة ذاتها، تعتمد قاعدة البيانات الحفظ الأخير وتُسجل التغييرات تفصيلياً في سجل التدقيق.

6. **طبيعة محرك SQLite والكاتب الأحادي (Single-Writer SQLite):**
   - قاعدة البيانات تدعم عدداً هائلاً من القراء المتزامنين، ولكن الكتابة تتم بتسلسل عبر كاتب أحادي وقفل محلي؛ لذا يُحظر تماماً وضع ملف قاعدة البيانات على مشاركات شبكية (SMB/NFS).

7. **دور مدير المكتب معلق (Role for "المدير" Pending Product Definition):**
   - الأدوار المعتمدة حالياً هي: `CHAIRMAN` (رئيس المجلس)، `SECRETARY` (السكرتارية)، و `ADMIN` (مدير النظام). تمثيل دور مستقل باسم "مدير المكتب" معلق بانتظار التوصيف الوظيفي والصلاحيات المعتمدة رسمياً من إدارة الهيئة.

## 4. أنماط التشغيل غير المدعومة (Unsupported Modes)

1. **النشر على الإنترنت العام المفتوح (Public Internet Deployment):** غير مدعوم ويعرض المنظومة لمخاطر غير مقبولة.
2. **الاستضافة السحابية العامة (Public Cloud):** غير مدعومة حالياً وتتطلب موافقة كتابية صريحة، وتوفير 2FA، وقرص تخزين دائم، ونسخ مشفر خارج الموقع.
3. **عناقيد قواعد البيانات الموزعة أو المشاركات الشبكية (DB Clustering / Shared Network Storage):** غير مدعومة قطعياً وتؤدي لتلف قاعدة بيانات SQLite.
